# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OpenWrite: a Windows desktop word processor (C# / .NET 10 / WPF) that replaces Microsoft Word for offline use and **opens and saves `.docx` directly** (no native format). Sister project of OpenPub (`/mnt/c/dev/open-pub`, Publisher replacement), from which the infrastructure is copied (files carry a `// Repris d'OpenPub 2.1.3 (…)` header). The UI, the online help and all code comments are in **French** — keep it that way. `PLAN.md` is the design document and running log (lots 0–15, decisions, calibrations, release history); read it before large changes and append a section when shipping a version. `INVENTAIRE-WORD.md` lists Word's features with priorities P0–P3.

## Environment (WSL + Windows toolchain)

Same as OpenPub: the repo lives on the Windows drive and is driven from WSL, but every .NET/WPF tool is the **Windows** one.

- .NET SDK is user-local: `D=/mnt/c/Users/prolice/AppData/Local/Microsoft/dotnet/dotnet.exe` (no `dotnet` on PATH). Run the debug app with `$D 'C:\dev\open-write\src\OpenWrite.App\bin\Debug\net10.0-windows\OpenWrite.dll' <args>` — the apphost `.exe` in bin/Debug won't find the runtime.
- Pass Windows paths (`$(wslpath -w ...)`) to Windows programs. When looping over files in bash, redirect `< /dev/null` for each `$D` call (it consumes stdin otherwise).
- `nuget.config` in the repo adds nuget.org (the user's global NuGet config has no sources).
- Word (licensed) is on this machine: `tools/export-reference-pdf.ps1` exports reference PDFs + `work/reference/references.csv` (pages, words, compat mode) through Word COM, read-only.

## Architecture (target: PLAN.md §3)

- **OpenWrite.Core** (net10.0) — pure logic. Signed update manifest (`Update/`), anonymised crash reports (`Diagnostics/`), recovery copies (`Io/RecoveryStore`) and atomic save with `.bak` + retries (`Io/SafeFile`). **Flow model prototype** (`Model/Flow.cs`, lot 1): `Story` → `Block` (`Paragraph`, `Table`/`TableRow`/`TableCell`, `BlockContentControl`, `OpaqueBlock`) → `Inline` (`Run`, `InlineContainer` for hyperlink/ins/del/smartTag…, `InlineContentControl`, `OpaqueInline`) → `RunContent` (`TextContent`, `TabContent`, `BreakContent`, `OpaqueRunContent`). Every node keeps **all original attributes**; properties are `PropertyBag`s holding the **original XML element** (typed get/set insert children in schema order, unknown extensions stay); anything not understood is an opaque `XElement`. `TextContent.LoadedValue`: untouched text is rewritten verbatim (`xml:space` only added to modified text). `FlowEdits`: insert text, split paragraph (new unique `w14:paraId`, sectPr stays on the last part). **Fields and bookmarks** (`Model/Markers.cs`): kept **flat like Word** — `FieldChar` (begin/separate/end, `ffData` kept as XML), `FieldCode` (instrText) are run contents; `BookmarkStart/End` are inlines (wrapped in `InlineMarkerBlock` between blocks, raw in table/row item lists). Structure is derived: `FlowWalker` (document-order events) → `FieldIndex` (code with nested fields as `{…}`, result text with `\r` between paragraphs, parent/children, `FormCheckBox` view), `BookmarkIndex` (pairs by id, covered text, hidden `_` names), `FieldInstruction` (type/args/switches parser). `MarkerOps`: `SetResultText`, bookmark add/rename/remove, Word name rules, `NextId`. Never restructure runs to build a field tree: it breaks the exact round-trip. **Positions**: `DocPos` (path of block indices — a table consumes 3: block, row item, cell item; a content control 1 — + character offset; `ParagraphAtoms` defines lengths: text/code = length, tab/break/field char/object = 1, markers = 0); positions never hold object references. **Editing** (`Core/Editing`): `TextOps.Insert/Delete/Split` (formatting inherited from the previous character; never inside tracked deletions), and the undoable wrappers `TextOps.Type/DeleteRange/SplitParagraph`. **Undo**: `UndoJournal` stores clones of the touched blocks before/after (by path), so any edit run inside `journal.Begin(label, root, containerPath, index, count)` … `Commit()` is undoable and rolled back if it throws; typing grouped by word; `MarkSaved`/`IsModified`; `Changed(root)` → mark the part `Dirty`. An edit must only touch blocks index..index+count of that container (it may insert/remove blocks there). **Styles** (`Core/Styles`): `StyleSheet` (styles, numbering, theme, settings — `DocxPackage.StyleSheet()`), `StyleResolver.Paragraph/Run/ParagraphMark/ListMarker` → `ParagraphFormat`/`RunFormat` (twips / points). Order **calibrated against Word via COM**: defaults → table style → paragraph style chain → **list level** (after the paragraph style, unlike ECMA; a style's list indent applies even when the paragraph sets `numId=0`) → character style → direct; toggle properties XOR across style levels; attribute-level merge for rFonts/ind/spacing/lang; theme fonts and colours (tint/shade in HSL luminance, matches Word's stored `w:val`). Still to come: conditional table-style formatting (lot 6), drawings/text boxes as nodes.
- **OpenWrite.Docx** (net10.0, DocumentFormat.OpenXml 3.x) — `DocxPackage`: reads the ZIP directly (tolerant, opens files Word rejects), maps document/headers/footers/notes/comments into the model (`StoryMapping`), keeps every other entry byte for byte; saves only `Dirty` parts (order, names, dates of entries kept), `NewLineHandling.Entitize` (newlines in attributes). `XmlCompare`: normalized diff + `ChangedSpan` (locality of an edit). `DocxInfo`: read-only summary used by the 0.1 UI (via the SDK).
- **tests/OpenWrite.Fidelity** — console bench over the local corpus (not xUnit): round-trip with every story part regenerated, byte check of other parts, text coverage, opaque-island stats, 5 local edits (text, bold, split, toggle form checkbox, add bookmark) with locality check, undo-all/redo-all through the journal (`refaire/`), `--stress` also times journaled typing, SDK validator before/after, export of OpenWrite's view of fields/checkboxes/bookmarks (`modele/*.json`). `tools/word-inspect.ps1` writes Word's view (COM, read-only) in the same JSON shape; `OpenWrite.Fidelity --compare-word <out dir>` compares them. Formatting: `OpenWrite.Fidelity --formats <docx dir> <json dir>` (resolved paragraph/first-character formatting + check of theme colours against Word's stored `w:val`) vs `tools/word-format.ps1` (Word COM), compared with `--compare-formats` (LCS alignment by text, row-end marks and theme colours from COM excluded). PowerShell 5.1 pitfall: `ConvertTo-Json` on a .NET list → pass `-InputObject $list.ToArray()` and cast to `[string]`.
- **OpenWrite.Layout** (net10.0) — lot 2 engine (PLAN.md §10.7). `Fonts.cs`: `FontFace` (advances/metrics in em), `IFontProvider` (`MonoFontProvider` for tests), `FontVerticalMetrics` (Word's single line = **GDI formula** win ascent + descent + external leading, even for USE_TYPO_METRICS fonts). `ParagraphLayout.cs`: `ParagraphLayouter.Content` flattens a paragraph's displayed text (field codes hidden, results shown, hidden/deleted text skipped, inline objects `\uFFFC` sized from `wp:extent`, breaks `\n \f \v`), `Layout` breaks lines (spaces, trailing spaces hang, tabs, list marker, line rules, paragraph mark in last line height). `Paginator.cs` `DocumentLayout`: sections, widows/orphans, keepLines, keepNext chains, contextual spacing, space before suppressed at top of a flow page, grouped paragraph borders, header/footer pushing the body (`related` = r:id → Story, `DocxPackage.RelatedStory`), tables by whole rows. Caches: paragraph layouts by **reference** (`ConditionalWeakTable`) + width; `Update(blocks)` relayouts from the page before the change and **converges** when a new page starts where an old one did (fast path for in-place edits). Not yet: columns, splittable rows, cell borders, floating objects, notes. Also `Hyphenator`.
- **OpenWrite.App** (WPF) — `MainWindow` split by domain: `.Ribbon.cs` (Word's tabs built from the `Roadmap` table: every group shows the version that will enable it; File menu, recent files), `.Document.cs` (0.2 workspace: welcome card, **formatted preview from the model** via `StyleResolver` — no pagination, page width/margins from the last section, tables as grids, field codes hidden/results shown, clickable form checkboxes; right pane describes the hovered paragraph), `.Editing.cs` (`DocxPackage` + `UndoJournal`: checkbox toggle, Undo/Redo, Save/Save As (same format family), `.bak`, confirm on close; `journal.Changed` → part `Dirty`), `.Recovery.cs` (OpenPub's autosave/recovery/external-change detection, `.docx` copies). `DocxInfo` (SDK) still feeds the info pane. Design system in `App.xaml` (OpenPub's styles `RBig/RSmall/RGroup/RibbonTab/PillButton`, recoloured to the OpenWrite brand: ink `#111A47`, blue `#087CFF`, cyan `#00C9D5`, orange `#FF8712`; gradient `Accent` blue→orange; `SoonBadge`/`VersionBadge` for "version x.y" chips). Infra from OpenPub: `Update/UpdateService`, `Diagnostics/CrashReporter`, `Help/HelpService`, `AboutWindow`, `AppSettings` (`%APPDATA%\OpenWrite\settings.json`).

Portal/update/crash/help URLs and the update public key are `AssemblyMetadata` in `OpenWrite.App.csproj`: portal = Azure Static Web App `openwrite-updates` (Free plan, resource group `rg-openwrite-updates`, West Europe) at https://gentle-glacier-0e0efdd03.3.azurestaticapps.net (`/latest.json`, `/api/crash`, `/aide/`). Azure CLI is the Windows one, wrapped by `tools/az.sh`. Subscription quotas: 980 resource groups (free), **10 Free Static Web Apps** (3 used: noise2quite, openpub, openwrite).

## Publication (same chain as OpenPub)

- **GitHub Actions**: `ci.yml` (build + xUnit on push/PR, Node tests of `tools/site-api`), `release-app.yml` (tag `vX.Y.Z` or manual with dry-run: tests → self-contained exe → WiX MSI `-p:ProductVersion` → signed `latest.json` → portal → GitHub release → Azure), `publish-portal.yml` (portal changes on main: rebuilds page + help from the latest release; does nothing but warn while there is no release). Secrets: `UPDATE_SIGNING_KEY` (PEM, also at `%APPDATA%\OpenWrite\update-signing-key.pem`), `AZURE_STATIC_WEB_APPS_API_TOKEN`; crash relay needs the SWA app setting `GITHUB_TOKEN` (issues on prolice/open-write).
- **Installer** `installer/` (WiX 5, per-user, own GUIDs; adds OpenWrite to "Open with" for .docx/.docm/.dotx/.dotm via `OpenWithProgids`, never the default handler). Local: `tools/build-installer.ps1`, `tools/publish-update.sh X.Y.Z "notes" [--deploy|--deploy-only]` — production deploys are blocked in auto mode: prepare locally and let the user deploy.
- **Portal** `tools/build-site.py` (+ `build-docs.py` help pages, `site-template/`, `fonctionnalites.json` with `"depuis"` for features not yet shipped). Screenshots use a neutral demo `.docx` written by `write_demo_docx` (never the corpus). Help anchors are checked against `--help-topics`. Free quota 250 MB: only the current MSI on the site (limit 230 MB); previous version = link to its GitHub release.
- `git push` from WSL has no credentials: use `git.exe` (Windows Git Credential Manager).

## Don'ts

- The future GitHub repo is **public**: `samples/` (real documents with personal data, including a child's name) and `work/` (reference PDFs) are git-ignored — never commit them, never put their content in tests, test strings, screenshots or the portal. Unit tests build their `.docx` in code with the Open XML SDK; captures for docs use neutral documents.
- **Never modify a user's document** in place without the safe-save path (`SafeFile.Write`, `.bak`). Until lot 1 ships, OpenWrite is read-only.
- Never save a `.docx` that silently lost content: what OpenWrite can't edit must be preserved (PLAN.md §5.3).
- Don't block the WPF UI thread on async work in CLI modes (`.GetAwaiter().GetResult()` deadlocks) — wrap in `Task.Run`.
- Help links: constants in `Help/HelpService.cs` must match anchors of the future `tools/build-docs.py`.
- The update signing private key will be `%APPDATA%\OpenWrite\update-signing-key.pem` (outside the repo).
