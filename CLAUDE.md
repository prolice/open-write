# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OpenWrite: a Windows desktop word processor (C# / .NET 10 / WPF) that replaces Microsoft Word for offline use and **opens and saves `.docx` directly** (no native format). Sister project of OpenPub (`/mnt/c/dev/open-pub`, Publisher replacement), from which the infrastructure is copied (files carry a `// Repris d'OpenPub 2.1.3 (…)` header). The UI, the online help and all code comments are in **French** — keep it that way. `PLAN.md` is the design document and running log (lots 0–15, decisions, calibrations, release history); read it before large changes and append a section when shipping a version. `INVENTAIRE-WORD.md` lists Word's features with priorities P0–P3.

## Environment (WSL + Windows toolchain)

Same as OpenPub: the repo lives on the Windows drive and is driven from WSL, but every .NET/WPF tool is the **Windows** one.

- .NET SDK is user-local: `D=/mnt/c/Users/prolice/AppData/Local/Microsoft/dotnet/dotnet.exe` (no `dotnet` on PATH). Run the debug app with `$D 'C:\dev\open-write\src\OpenWrite.App\bin\Debug\net10.0-windows\OpenWrite.dll' <args>` — the apphost `.exe` in bin/Debug won't find the runtime.
- Pass Windows paths (`$(wslpath -w ...)`) to Windows programs. When looping over files in bash, redirect `< /dev/null` for each `$D` call (it consumes stdin otherwise).
- `nuget.config` in the repo adds nuget.org (the user's global NuGet config has no sources).
- Word (licensed) is on this machine: `tools/export-reference-pdf.ps1` exports reference PDFs + `work/reference/references.csv` (pages, words, compat mode) through Word COM, read-only. `tools/word-make-tables.ps1 <dir>` has Word write neutral calibration documents (tables, style gallery; French style names); `tools/pdf-to-png.ps1 <pdf> <dir> [pages] [width]` rasterizes Word's PDFs (Windows PDF reader) for visual comparison. `tools/word-make-drawings.ps1 <dir>` writes float/wrap calibration documents, `tools/word-lines.ps1 <docx dir> <json dir>` records every body line Word laid out (page, top, left, width, length) for `OpenWrite --lines <docx dir> <json dir> [--detail]`. Word COM: `Documents.Add` + `Range.Paste`/`SaveAs2` sometimes hangs invisibly — dump `Content.WordOpenXML` instead and kill only the Word process you started.
- Environment variables set in WSL do **not** reach the Windows .NET process unless listed in `WSLENV` (e.g. `WSLENV=OPENWRITE_BENCH_DUMP:OPENWRITE_LAYOUT_TRACE`).

## Architecture (target: PLAN.md §3)

- **OpenWrite.Core** (net10.0) — pure logic. Signed update manifest (`Update/`), anonymised crash reports (`Diagnostics/`), recovery copies (`Io/RecoveryStore`) and atomic save with `.bak` + retries (`Io/SafeFile`). **Flow model prototype** (`Model/Flow.cs`, lot 1): `Story` → `Block` (`Paragraph`, `Table`/`TableRow`/`TableCell`, `BlockContentControl`, `OpaqueBlock`) → `Inline` (`Run`, `InlineContainer` for hyperlink/ins/del/smartTag…, `InlineContentControl`, `OpaqueInline`) → `RunContent` (`TextContent`, `TabContent`, `BreakContent`, `OpaqueRunContent`). Every node keeps **all original attributes**; properties are `PropertyBag`s holding the **original XML element** (typed get/set insert children in schema order, unknown extensions stay); anything not understood is an opaque `XElement`. `TextContent.LoadedValue`: untouched text is rewritten verbatim (`xml:space` only added to modified text). `FlowEdits`: insert text, split paragraph (new unique `w14:paraId`, sectPr stays on the last part). **Fields and bookmarks** (`Model/Markers.cs`): kept **flat like Word** — `FieldChar` (begin/separate/end, `ffData` kept as XML), `FieldCode` (instrText) are run contents; `BookmarkStart/End` are inlines (wrapped in `InlineMarkerBlock` between blocks, raw in table/row item lists). Structure is derived: `FlowWalker` (document-order events) → `FieldIndex` (code with nested fields as `{…}`, result text with `\r` between paragraphs, parent/children, `FormCheckBox` view), `BookmarkIndex` (pairs by id, covered text, hidden `_` names), `FieldInstruction` (type/args/switches parser). `MarkerOps`: `SetResultText`, bookmark add/rename/remove, Word name rules, `NextId`. Never restructure runs to build a field tree: it breaks the exact round-trip. **Positions**: `DocPos` (path of block indices — a table consumes 3: block, row item, cell item; a content control 1 — + character offset; `ParagraphAtoms` defines lengths: text/code = length, tab/break/field char/object = 1, markers = 0); positions never hold object references. **Editing** (`Core/Editing`): `TextOps.Insert/Delete/Split` (formatting inherited from the previous character; never inside tracked deletions), and the undoable wrappers `TextOps.Type/DeleteRange/SplitParagraph`. **Undo**: `UndoJournal` stores clones of the touched blocks before/after (by path), so any edit run inside `journal.Begin(label, root, containerPath, index, count)` … `Commit()` is undoable and rolled back if it throws; typing grouped by word; `MarkSaved`/`IsModified`; `Changed(root)` → mark the part `Dirty`; `EditTransaction.TrackXml(root)` snapshots an XML part (styles/numbering/theme) restored in place on undo/redo/failure (`XmlChanged`, `LastXml`); `LastChange` (container, first block, block count after the operation — also after undo/redo) drives the incremental relayout. `TextOps.InsertSpecial` (tab, line/page break), `InsertMultiline`/`Replace` (selection replaced or paste, one undo step), `Split` with `nextStyle` (Enter at paragraph end: w:next style, else the mark takes the last character's formatting). **Direct formatting** (`FormatOps`): `ApplyToRuns` splits runs at the range bounds (`SplitRunAt`) and applies to each run; `SetToggle` (b/i + bCs/iCs, `val=0` when the style still sets it), `SetUnderline`, `SetValue`, `SetFont`; `ApplyToParagraphs`; `Apply` wraps in a journal transaction; `SetIndent/SetSpacing/SetParagraphFlag/ClearCharacter/ClearParagraph`; `Normalize` (range leaving a table → top-level, touched table taken whole, see `TextOps.AcrossTopLevel/DeleteAcross`). `TextOps.ReplaceText` (find/replace: new text takes the first replaced character's formatting). **Clipboard model** (`Fragments`): `Extract` (clones cut at the bounds, bookmarks/comments/note refs/sectPr/paraIds dropped, `EndsWithParagraph`), `Insert`/`Paste` (last partial paragraph merges into the target and takes its props), `Build` from `Core/Interop` `RtfReader`/`HtmlReader` (`ParaSpec`, `CharFormat`). `LinkOps` (hyperlink at offset, wrap a range, unwrap, retarget); `DocxPackage.AddExternalRelationship`. An edit must only touch blocks index..index+count of that container (it may insert/remove blocks there). **Styles** (`Core/Styles`): `StyleSheet` (styles, numbering, theme, settings — `DocxPackage.StyleSheet()`), `StyleResolver.Paragraph/Run/ParagraphMark/ListMarker` → `ParagraphFormat`/`RunFormat` (twips / points). Order **calibrated against Word via COM**: defaults → table style → paragraph style chain → **list level** (after the paragraph style, unlike ECMA; a style's list indent applies even when the paragraph sets `numId=0`) → character style → direct; toggle properties XOR across style levels; attribute-level merge for rFonts/ind/spacing/lang; theme fonts and colours (tint/shade in HSL luminance, matches Word's stored `w:val`). **Lot 4**: `StyleOps` (styles found by built-in `w:name`, never by id — ids are localized; French display names; Word 2013+ definitions of built-in styles written to styles.xml on first use; `Create`, `Capture/Merge/Absorb` for new style / update from selection, `Editable` exposes a style's pPr/rPr as a Paragraph/Run for the Font/Paragraph dialogs, `SetStyleValue` in schema order), `ListOps` (Word's default bullet/numbered definitions, headings list linked to Heading 1–3, restart via lvlOverride/startOverride, set/remove numPr), `ThemeOps` (font pairs, colour palettes in theme1.xml). **Lot 5**: `SectionOps` (section of a block, paper/orientation — margins rotate like Word —, margins, columns, page numbering, page borders, line numbers, `InsertBreak`: the section before keeps props and header refs, the one after gets the type and inherits headers), `FieldOps.Insert` (complex field PAGE/NUMPAGES…). Journal: `TrackStory` (other stories, e.g. all headers for a watermark, in the same undo step). **Lot 6**: `TableStyles` (regions from `w:tblLook` — matches Word's `w:cnfStyle` —, `CellStyle` = table style + regions passed to the resolver; `StyleResolver.TableLevel` merges the style and its `w:tblStylePr` in Word's order, `TableStyleProps` = style tblPr chain), `TableStyleOps`/`TableStyleDefs` (gallery: Table Grid + 5 families × 7 colours, written on first use with Normal Table; theme colours recomputed, Office-theme constants kept — 36/36 identical to Word), `TableOps` (`Map` = grid view with gridBefore/gridSpan/vMerge; create like Word, insert at caret, rows/columns, merge, split, split table, boundaries, widths/heights, distribute, shading, borders like Word's menu, alignment, margins, style/look, header rows, autofit, text ↔ table, sort, formulas, `Extract` for copying cells). `Interop/HtmlTableReader`: clipboard HTML tables → model tables like Word's paste from Excel (table searched in the whole CF_HTML since Excel puts `<table>` before StartFragment; `<style>` CSS + inline; widths from `<col>`, row heights, per-side borders, padding, alignments, colspan/rowspan; paragraphs around a web table kept); tried before RTF on paste. **Lot 7** (`Core/Drawing`): `DrawingContent` run content (w:drawing, w:pict, w:object, mc:AlternateContent; `Xml` with emptied w:txbxContent, their text in `TextBoxes` stories written back on save; the VML fallback has its own stories, synced from the DrawingML one after edits). `DrawingReader` → `DrawingObject` (frame, effect extents, anchor axes, wrap, distances, polygon, behind, Z) + `Visual` tree (picture, shape, group, fallback); theme colours and shape styles; VML (CSS style, w10:wrap, o:hr rules). `ShapeGeometry` evaluates the 187 official preset shapes (`presetShapeDefinitions.xml`, embedded) and custGeom. `DrawingOps` writes size, position, wrap, inline ↔ anchor, Z, rotation, flip, crop, alt text, fill, line, corrections, geometry; creates pictures, shapes and text boxes like Word; renumbers docPr ids.
- **OpenWrite.Docx** (net10.0, DocumentFormat.OpenXml 3.x) — `DocxPackage` (`AddImage`: media part + relationship + content type; `EnsureDrawingNamespaces`): reads the ZIP directly (tolerant, opens files Word rejects), maps document/headers/footers/notes/comments into the model (`StoryMapping`), keeps every other entry byte for byte; saves only `Dirty` parts (order, names, dates of entries kept), `NewLineHandling.Entitize` (newlines in attributes). `XmlPartOf("styles"|"numbering"|"theme"|"settings", create)`, `CreateHeaderPart(kind)` (new headerN/footerN part, relationship, content type): live editable XML parts (created with relationship + content type override when missing, never the theme), rewritten only when `Dirty`; `StyleSheet()` reads those same objects. `AddExternalRelationship` (hyperlinks). `XmlCompare`: normalized diff + `ChangedSpan` (locality of an edit). `DocxInfo`: read-only summary used by the 0.1 UI (via the SDK).

Not yet: notes continued on the next page. Also `Hyphenator`. **Caret** (`Caret.cs`, lot 3): `ParagraphContent.ModelStart/ModelEnd` map each displayed character to its `DocPos` offset range (a checkbox or computed PAGE value covers the whole field); `TextPoint` (paragraph + displayed index + `AtLineEnd`); `CaretGeometry` (model offset ↔ display index — typing goes after the previous character, never into a field code —, X of a caret with justification/tabs, `IndexAtX`, `LineOf`, words); `DocumentLayout.LinesOf(paragraph)` → `LineRef` (page, index in `Page.Lines`), `Line(ref)`, `Step(ref, ±1)`.

## Publication (same chain as OpenPub)

- **GitHub Actions**: `ci.yml` (build + xUnit on push/PR, Node tests of `tools/site-api`), `release-app.yml` (tag `vX.Y.Z` or manual with dry-run: tests → self-contained exe → WiX MSI `-p:ProductVersion` → signed `latest.json` → portal → GitHub release → Azure), `publish-portal.yml` (portal changes on main: rebuilds page + help from the latest release; does nothing but warn while there is no release). Secrets: `UPDATE_SIGNING_KEY` (PEM, also at `%APPDATA%\OpenWrite\update-signing-key.pem`), `AZURE_STATIC_WEB_APPS_API_TOKEN`; crash relay needs the SWA app setting `GITHUB_TOKEN` (issues on prolice/open-write).
- **Installer** `installer/` (WiX 5, per-user, own GUIDs; adds OpenWrite to "Open with" for .docx/.docm/.dotx/.dotm via `OpenWithProgids`, never the default handler). Local: `tools/build-installer.ps1`, `tools/publish-update.sh X.Y.Z "notes" [--deploy|--deploy-only]` — production deploys are blocked in auto mode: prepare locally and let the user deploy.
- **Portal** `tools/build-site.py` (+ `build-docs.py` help pages, `site-template/`, `fonctionnalites.json` with `"depuis"` for features not yet shipped). Screenshots use a neutral demo `.docx` written by `write_demo_docx` (never the corpus). Help anchors are checked against `--help-topics`. Free quota 250 MB: only the current MSI on the site (limit 230 MB); previous version = link to its GitHub release.
- `git push` from WSL has no credentials: use `git.exe` (Windows Git Credential Manager).

## Don'ts

- The future GitHub repo is **public**: `samples/` (real documents with personal data, including a child's name) and `work/` (reference PDFs) are git-ignored — never commit them, never put their content in tests, test strings, screenshots or the portal. Unit tests build their `.docx` in code with the Open XML SDK; captures for docs use neutral documents.
- **Never modify a user's document** in place without the safe-save path (`SafeFile.Write`, `.bak`). Until lot 1 ships, OpenWrite is read-only.
- Never save a `.docx` that silently lost content: what OpenWrite can't edit must be preserved (PLAN.md §5.3).
- Don't block the WPF UI thread on async work in CLI modes (`.GetAwaiter().GetResult()` deadlocks) — wrap in `Task.Run`.
- Help links: constants in `Help/HelpService.cs` must match anchors of the future `tools/build-docs.py`.
- The update signing private key will be `%APPDATA%\OpenWrite\update-signing-key.pem` (outside the repo).
